# 安全范围与测试机验收

## 已采用的限制

服务以专用 xs-ui 用户运行，程序归 root 所有；仅授予绑定低端口能力，没有网络管理能力。系统目录只读、私有临时目录、数据库及证书目录限制权限。后台和订阅不直接对公网监听，SSH 隧道作为默认管理入口。安装和节点密码使用密码学随机源生成。

快捷创建沿用 S-UI 既有登录会话与同源请求防护，不增加公开免登录管理接口或远程执行命令接口。节点先停用，凭据绑定核对后才启用。Reality 私钥不进入客户端链接，Hysteria2 不启用 insecure。节点凭据需要保存到面板数据库，数据库和备份本身都是敏感文件；“浏览器不持久保存”并不代表服务器不保存。

安全范围是降低新功能及默认安装的风险，没有做完上游所有代码和依赖的独立审计。服务器安全更新、SSH 登录策略、云安全组、主机防火墙仍需要按实机状态处理。不要宣称“安全加固已全部完成”。私有仓库不是服务器访问密码，也不能阻止有源码的人复制程序。

系统 TCP BBR 配置不限制节点带宽；Hysteria2 使用自身的 QUIC 拥塞控制。不要盲目调整数十项 sysctl 或替换内核；只有有明确测量依据才增加优化。

## 必须补齐的实机验收

1. 通过 `tools/preflight.sh` 收集系统、架构、内核、内存、依赖、相关端口和 BBR 状态。不收集密码、私钥、环境变量或完整服务器配置。
2. 独立备份或确认空机；确认 SSH 可重新登录，云控制台可用于救援。核实公网 DNS A/AAAA 及可用节点端口。
3. 用准备发布的同一安装包/命令安装，确认服务 active、非 root 运行、管理与订阅仅监听本机、随机凭据可登录。
4. 验证系统 BBR 配置当前值、持久文件及备份；以后安排一次受控重启后再复核，未经复核不称“重启持久性已验证”。
5. 在图形界面创建 Hysteria2，确认真实证书签发、有效期及主机名；真实客户端保留证书验证且能联网。续期流程需要额外测试，首次签发不代表续期已验证。
6. 创建 Reality，客户端导入测试；SOCKS5 检查无认证、错误密码均失败，正确认证能代理。管理端口从公网不可达。
7. PassWall2、V2RayN 与指纹浏览器分别实测。多个节点可以并存，但同一连接采用哪个出口由客户端路由决定。
8. 观察 768 MB 目标机峰值内存、日志增长、磁盘占用及持续运行。100 Mbps 实测速率、UDP 可达性、晚高峰稳定性、服务商流量计费另测，不从本地单测推断。
9. 按云安全组和主机现状最小化放行端口；验证密钥新会话后再考虑禁用 SSH 密码登录。核实自动安全更新与恢复方式，避免自动升级主内核或无通知重启。

## 目前阻塞

开发环境直连腾讯云 SSH 的 TCP 连接返回 Network is unreachable，没有执行任何服务器改动。用户授权已经存在，不是需要再次提供密码。GitHub 网页登录流程被自动审批拒绝，CLI 也没有已认证会话，代码和 Release 尚未上传。先交付可复核文件，再通过用户自己的已登录终端/仓库上传路径完成实际部署。
