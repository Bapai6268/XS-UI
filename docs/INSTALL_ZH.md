# 发布和安装说明

## 目前可用程度

这份包可以在你指定的空白测试 VPS 上做安装验收，但尚未完成实机验收。`v0.1.0-dev.2` 是准备发布的版本号，**未上传到 GitHub**，不能把下述远程命令当成已经可用的下载地址。

现有生产服务器不动。安装器遇到已有 XS-UI 专用目录、服务账号、数据库或占用的管理端口就停止，不覆盖原数据。它不是升级器，安装中途失败也不能靠反复运行来自动修好。

## 私有仓库怎样放文件

仓库使用你创建的 `Bapai6268/XS-UI`，保持 Private。

源码包 `XS-UI-source-dev.2.zip` 解压后，把 XS-UI 文件夹内的内容提交到该仓库根目录。不要把整个压缩包当成源码提交；不要上传服务器数据库、证书私钥、SSH 密钥、节点链接或管理员密码。可使用 GitHub Desktop 克隆该空仓库，再复制源码、提交和 Push。源码含许可证，不需要另选一个许可证覆盖它。

在 GitHub 仓库的 Releases 中创建 **预发布** `v0.1.0-dev.2`，附加交付包 `release-assets/` 下的两个文件：

- `XS-UI-linux-amd64.tar.gz`
- `SHA256SUMS`

发布说明写清“开发测试版，尚未完成 VPS/公网代理验收”。源码内 `install.sh` 固定下载这个版本，不追随不断变化的 latest。发布前后都应核对两个文件的名称。

校验和只能检查下载包与清单一致；清单和包同源，不能抵御 GitHub 账号或发布权限被攻破。请为 GitHub 账号开启两步验证，并保护登录设备。当前没有配置独立签名发行体系。

## 在空白测试 VPS 本地安装（不依赖 GitHub 登录）

从交付包取出 `release-assets/XS-UI-linux-amd64.tar.gz`，用你自己的 SSH 客户端上传到服务器。也上传对应 `SHA256SUMS`。在同一目录执行：

```bash
sha256sum -c SHA256SUMS
mkdir xs-ui-package
tar -xzf XS-UI-linux-amd64.tar.gz -C xs-ui-package
sudo bash xs-ui-package/install-local.sh
```

仅对这份你已取得、来源明确且校验成功的包执行。先解压再安装不是“在线一键下载”，它是浏览器/私有仓库授权暂不可用时的测试路径。

## 发布后，在新 VPS 用命令安装

私有仓库不能匿名下载。不能同时做到“任何机器无需授权就下载”和“只有你能下载”。首次需在新服务器安装 GitHub CLI，并通过 `gh auth login --hostname github.com` 授权有权读取该仓库的账号；不要把 Token 发到聊天或写入安装命令。GitHub CLI 的具体安装方式依发行版确定，先看只读检查结果。

授权并发布完成后，以下相同命令用于支持的 Ubuntu/Debian x86_64 机器：

```bash
gh repo clone Bapai6268/XS-UI && bash XS-UI/install.sh
```

这是已授权后的安装入口，不是当前已验证成功的命令。脚本下载固定 Release、校验、检查包内容，再通过 sudo 安装。首次 GitHub 授权和 sudo 验证可能需要交互，因此不是完全无人值守。

为减少服务器上的长期 GitHub 凭据，个人使用更推荐在自己的电脑下载私有 Release 后上传安装。若在临时 VPS 登录过 gh，完成后执行 `gh auth logout --hostname github.com` 清除本机登录，并在 GitHub 的授权设置中撤销临时授权；本机登出不等于远程撤销令牌。

## 如何打开图形面板

安装成功后，在**你的电脑终端**建立 SSH 隧道：

```bash
ssh -N -L 2095:127.0.0.1:2095 ubuntu@115.159.42.145
```

保持这个窗口运行，电脑浏览器打开 `http://127.0.0.1:2095/app/`。该 HTTP 连接从电脑经加密 SSH 隧道传到服务器，公网不开放后台 2095 端口。SSH 端口如果不是 22，需要加 `-p 实际端口`；新 VPS 的用户名/IP 也要替换。

在已登录服务器的 SSH 窗口用 `sudo cat /root/xs-ui-access.json` 查看随机管理员凭据，仅自己查看，不截图发给别人。保存到密码管理器；创建节点时同样保护导入链接。

## 域名、节点和端口

腾讯测试域名是 `bapai.ccwu.cc`，截图中的 A 记录指向 `115.159.42.145`，灰云“仅 DNS”。实际公共 DNS、IPv6 AAAA 记录及云防火墙仍需检查。以后新 VPS 要更新该记录或换新子域名。

| 用途 | 需要的连接 |
|---|---|
| SSH 管理及面板隧道 | 服务器实际 SSH TCP 端口；保持现有访问方式 |
| 自动证书签发/续期 | TCP 80，必须空闲且外部可达 |
| Hysteria2 | 所选 UDP 端口 |
| VLESS Reality | 所选 TCP 端口 |
| SOCKS5 默认本机模式 | 不需要开放公网端口，通过 SSH 隧道或本地代理链路使用 |

安装器不自动更改云安全组或主机防火墙，也不关闭 SSH 密码登录。实机阶段先核实 SSH 密钥能从新会话成功登录，再安排 SSH 加固，避免把自己锁在服务器外。

Hysteria2 自动申请模式需要自己的域名和证书联系邮箱，并确认服务条款；不是复用旧服务器证书。Reality 需要填写 VPS 可达且适用的 TLS 1.3 目标域名。首次保存后要看核心日志并实测，不要用“跳过证书验证”修复失败。

## 失败时怎么办

安装失败会返回非零，不会显示成功。先保留现场并查看 `sudo systemctl status xs-ui --no-pager`、`sudo journalctl -u xs-ui -n 100 --no-pager`。分享日志前遮掉凭据和节点链接。不直接删除数据库或反复运行安装器。

BBR 原值存放在 `/var/lib/xs-ui-install/network-before.json`，持久配置在 `/etc/sysctl.d/90-xs-ui-bbr.conf`；它们与业务数据独立。BBR 不支持时不会换内核。BBR 设置过程中出错会尝试恢复原运行值；恢复失败会明确报错，需要人工核对。

创建节点失败可能保留停用节点、账号或 TLS 记录；先到原面板中检查，不立即重复点击。激活失败也可能影响核心运行，应先停用本次新入站并检查日志。当前没有把整个证书申请和节点激活实现为可自动回滚的事务。
